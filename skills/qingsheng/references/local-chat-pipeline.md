# 本地导出聊天记录分析管线（local-chat-pipeline）

本文件为 **pickled-fish 仓库新增**，衔接：

- 上游情圣知识库（`../SKILL.md` + 其他 `references/*`）
- macOS 导出产物 `chat.txt`（见 `../../wechat-mac-export/`）

当用户提供的是**完整导出**（数百～数万行），不要假装「已通读每一句」。按下面步骤做**可复现**的本地分析。

---

## 1. 识别输入

| 输入 | 处理 |
|------|------|
| `chat.txt` 路径（WxEcho 风格） | 脚本统计 + 抽样关键日 |
| 粘贴片段 / 截图 | 走情圣默认流程，不必上全量统计 |
| 未导出 | 先 `wechat-mac-export`，再回来 |

常见行格式：

```
[YYYY-MM-DD HH:MM:SS] 我: ...
[YYYY-MM-DD HH:MM:SS] <对方昵称>: ...
[YYYY-MM-DD HH:MM:SS] 系统: ...
```

---

## 2. 建议统计（用 Shell/Python，结果摘要进对话）

在用户机器上对 `chat.txt` 计算（示例指标）：

- 总条数、双方条数比、时间跨度  
- 谁更常「每日首条」  
- 你的连发：短窗口内连续 ≥3 条的次数  
- 关键词计数（按中文语境调整）：  
  - 你：`对不起` / `抱歉` / `别生气` / `好不好` / 撤退类（`拜拜`/`不玩了`/`删`）  
  - 对方：`不要` / `别` / `不想` / 边界类（`结束`/`互删`/`报警`/`两清` 等，若出现）  
- 最后 7～15 天每日条数  
- 崩盘日：单日你方消息异常高、或出现拉黑/删除/系统「拒收」  

把**数字摘要**给用户，不要贴出大段隐私原文，除非用户要求看某一天。

---

## 3. 时间线（只抽关键节点）

优先用 `rg`/`grep` 搜对方原话中的边界与关系定位，例如：

- 不想谈 / 只打游戏 / 不合适  
- 结束了 / 互删 / 拉黑 / 两清 / 报警  
- 压力 / 极端 / 算计  

输出一条简短时间线（日期 + 一句原话摘要），再进入情圣阶段判断。

---

## 4. 接到情圣框架

1. 读 `stages.md` 定阶段（有完整历史时更准）  
2. 信号用 `signals-tools.md`（IOI/IOD、压力、需求感）  
3. 分手 / 拉黑 / 明确拒绝 → **必须**读 `recovery-playbook.md`  
4. 仍用情圣节奏：**1–2 关键点 + 1 个追问**；长报告是失败模式  

### 全量导出时的额外诚实原则

- 统计上的「你发得更多 / 连发多」→ 解释为**需求感或焦虑模式**，给可执行改法，不羞辱  
- 对方多次「只能…」「不要…」→ 尊重边界，不硬推升级  
- 若已出现报警、上门、反复加好友等 → 挽回评估应偏 **低可能**，优先冷静期与停止接触  

---

## 5. 事务消息 vs 情感消息

导出后对方若只谈退款、快递、物品：

- 默认按**两清/收尾**理解，不是复合信号  
- 回复建议：**一句确认、可复制、不续聊**  
- 不要把长文道歉/分析截图发给对方  

情感挽回另开时间线（见 recovery-playbook），不要绑在物流/金钱对话里。

---

## 6. 输出模板（全量分析时）

```markdown
## 数据摘要
- 跨度 / 条数 / 双方比 / 连发与关键词要点

## 关系阶段（情圣）
- 阶段 + 一句依据

## 关键结论（最多 2 条）
1. ...
2. ...

## 下一步
- 若可发送：给出原文
- 若不应联系：明确写「先不发」+ 冷静期建议

## 追问
- 一个具体问题
```

---

## 7. 隐私

- 分析在用户本机对话中完成；默认不上传 chat.txt  
- 开源示例与文档中禁止粘贴真实姓名、wxid、手机号、原文长聊
